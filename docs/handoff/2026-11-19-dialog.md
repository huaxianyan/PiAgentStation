# 交接：对话区细节与追加输入队列（2026-11-19）

## 这轮做了什么

按原型（`work/proto-ux/`，未入库）把六条界面问题落进 `src/SevenStation.Core/wwwroot/` 与 `CenterHub.cs`：

1. **用户气泡**：右对齐、宽度上限 78%/600 px、右下角收小；三档色（跟随主题 / 微信绿 / 薄荷）
   由 `<html data-bubble>` 决定，色值在 `styles.css` 的 `--bubble-user*`。
   设置页「外观」卡现在是「主题 / 配色 / 用户气泡」三组，各带一行小标签。
2. **输入区**：`.composer-box` 常驻灰影，`:focus-within` 叠 `--focus` 光环且保留灰影；
   `.hint` 用 `min-height: calc(8px + 1.6em)` 固定预留一行（原来空着就 `display:none`，出现时把卡片顶上去了）；
   `.thread-inner` 底留白 44 px（放在滚动内容里，往上翻不占视口）。
3. **步骤**：`workGroup()` 在 `since > 0`（还在跑）时只渲染最后一条；跑完展开才看全部。
4. **悬停不闪**：`patchItem()` 对「正在跑且还没有正文」的那一轮走 `updateLiveTurn()`，
   只改 `step-row` 里的文字节点；步骤详情展开着时不走这条路（详情是旧内容，交给整轮重画）。
5. **滚动**：`atBottom()` 阈值 90 → 24；`message_start` 与用户消息落地从 `scrollToBottom(true)` 改 `false`。
6. **追加输入**：改由 Core 自持队列。

## 队列设计（用户选的是方案 C）

- 客户端不再给 `prompt` 带 `streamingBehavior`；Core 在 `live.Streaming` 时把 `prompt` 存进
  `Live.Queue`，广播 `queue_state`，`session_state.state.queue` 里也带一份，重开对话能还原面板。
- 命令：`queue_edit {id, message}`、`queue_remove {id}`、`queue_clear`。
- 送出：`agent_settled` 时发一条 `prompt`，剩下等下一轮，保证「一次一条、按顺序」。
- `live.Streaming` 在发出 `prompt` 时置 true（Pi 的 `agent_start` 不保证每次都来），
  `agent_end` / `agent_settled` 置 false。**不要在两个事件里都触发投递**，会把整队一次送完（踩过）。
- 图片随条目一起存（`JsonArray` 深拷贝），但界面只显示文本；图片目前没有单独的展示。

## 测出来的两个问题（已修）

- **面板不出现**：`queue_state` 是顶层消息，我一开始把分支写进了 `onEvent()`（那里只收 `event.xxx`
  子事件），永远走不到。已搬到顶层分发。教训：加消息分支先确认它在分发层还是事件层。
- **按停止后排队内容自己送出去**：`agent_settled` 带 `aborted` 标记（pi 的 `_emitAgentSettled` 里是
  `_agentRunAbortRequested`），没判断就等于把「停止」当成「本轮正常结束」。现在停止了不投递，
  条目留在面板里等人处理。

## 追加输入的编辑方式（用户 2026-11-19 确认）

编辑不是面板内联输入框，而是**取回下面的输入框**改：点铅笔 → 该条高亮、标题变
「正在编辑第 N 条 · Enter 保存，Esc 取消」、正文搬进输入框；Enter 存回原位，Esc 放弃；
内容清空后回车算放弃（条目保留），删条目用叉。编辑期间该条被送出或删除会自动退出编辑态。

## 发送状态三态（2026-11-19 用户定稿）

- 气泡左边 14px 小圈：`sending` 灰圈转、送达淡出（220ms）、失败红圆底挖空感叹号。
- 失败点圈弹小面板：取消 / 删除这条 / 重新发送；重发走 `retryEcho()`，带原文与图片。
- 去掉红边（用户明确不要）；失败时消息留在原地，不再撤掉。
- 回显条目带 `echo`/`state`，`renderThread()` 末尾单独补画未确认的那些；确认后把同一条对象就地
  改成正牌（改 id/text/ts，state 变 `sent`），只淡出圈，避免闪一下。
- 演示：`SEVENSTATION_DEBUG_FAIL_PROMPT=1` 让每句话都失败。

## 正文里的地址与路径（2026-11-19）

- `decorateLinks()` 包在 `renderMarkdown()` 外层，扫描文本节点（跳过 `a`/`code`/`pre`），
  识别 `http(s)://`、`C:\...`、`\\server\share`；句末标点与右括号会trim掉。
- 网址 `target=_blank`；路径发 `reveal_path`，Core 用 `explorer.exe` 打开（文件用 `/select,`），
  只接受绝对路径且必须存在，失败回 `notice`。
- 新消息类型 `notice {text, kind}` → 客户端 `toast`。

## 批二补一条：发送立刻可见

- `submitPrompt()` 发之前先 `echoPrompt()` 画进对话并置 streaming，`work N 秒` 立刻开始；
  收到真正的用户消息后按 `echo: true` 找出来 `splice` 掉再画正牌，不重复。
- 排队（工作中回车）不回显——那条还没发出去，面板才是它的位置。
- 失败时 `dropEchoes()` 撤掉；`process_exit` 会整个会话丢掉，回显自然消失。
- 用户已确认：发送后立刻看到气泡、停止键与计秒同时切换、没有重复的用户消息。

## 批二：三处假状态（已做，2026-11-19）

- **侧栏「工作中」**：状态变化统一走 `SetStreaming(live, value)`，它只在值真的变时
  `BroadcastConversations()`；`agent_start` / `agent_end` / `agent_settled` / 发 prompt /
  投递排队都改用它。别再直接写 `live.Streaming = ...`，那样侧栏不刷新。
- **新对话的模型**：`StateWithModel()` 在 `conversation.Model` 为空时读
  `<agent>/settings.json` 的 `defaultProvider` + `defaultModel`，用缓存模型列表补全字段塞进
  `state.model`。界面上不再兜到列表第一条（GLM-5.2）。
- **模型缓存**：`modelsAt` 时间戳 + 24 小时 TTL；`list_models` 带 `force: true` 强制重取，
  模型面板底部有「刷新」按钮。
- 实测（8899 临时实例）：`state.model` 是 `magpie/auto/deepseek-v4.1-flash`；
  `conversation_list` 开工时 `working=true`、收工时 `working=false`；`modelsAt` 已落库。
