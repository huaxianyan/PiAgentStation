## 当前状态

- 会话：按磁盘扫描会话列表（同时支持默认的分目录布局和 `--session-dir` 的扁平布局），
  按工作目录分组，点击可续聊；新建会话走系统目录选择框。
- 对话：流式正文、思考块折叠、工具卡片（状态、参数摘要、耗时、参数与输出）、
  流式期间按钮变「停止」、回车插入引导消息。
- 扩展：`setStatus` 落侧栏底部，`setWidget` 落输入区上方，`notify` 落右下角提示，
  `select` / `confirm` / `input` / `editor` 走居中模态。

  前端从 `chrome.webview` 桥换成 `/ws?token=`。

  - 冒烟脚本通过：连接状态「已连接」、新会话、流式、收尾、侧栏刷新。

  - 桌面窗口发一条消息，第二个客户端收到同一条 `text_delta` 与 `agent_settled`，key 一致。

## 关窗口必崩的定位与修复（2026-11-18）

用户反馈：客户端关窗口一定报错，之前的版本也一样。查下来有两层原因。

**第一层（已修）**：关窗口时 WebView2 没有被显式释放，要等 GC 才收，那时 WPF 已经把窗口
拆掉了，浏览器回收 GDI 资源正好踩空，进程在 `gdi32full.dll` 里 `0xc0000409`（事件日志里
是 BEX64）。改法是在 `OnClosing` 里先 `Web.Dispose()`。验证：连续 4 次开窗再关（其中一次
是在流式回复中途关），进程都干净退出，事件日志没有新的崩溃记录。

**第二层（本机环境，需要用户操作）**：MacType 仍在往客户端进程里注入
（`MacType64.dll`、`Easyhk64.dll`、`MacType64.Core.dll`，进程模块列表和 WER 报告里都能看到）。
它的 `[ExcludeModule]` 段自己写着「不渲染的程序，但仍会加载 DLL」——加在那里只能不渲染，
DLL 照样注入，所以仍会随机崩在 `gdi32full.dll`，甚至启动阶段就崩（日志里只有「启动」没有
「加载中心页面」）。真正能阻止注入的是 `MacType.ini` 的 `[UnloadDll]` 段。

伴随现象：崩过的进程会留下 0 线程、0 句柄的僵尸进程，`Stop-Process` 和 `taskkill /F` 都报
「拒绝访问」，重启才清。僵尸在的时候新实例起不来（日志只有「启动」一行）。

新增 `scripts/close-smoke.ps1`：开窗 → 关窗 → 查事件日志，崩了就返回非零。
`window.json` 也改成先写 `.tmp` 再换名，避免上次崩溃留下的空文件被当成有效配置。

**复查（2026-11-18 00:45 之后）**：用户把 `PiAgentStation.exe` 写进 `MacType.ini` 的
`[UnloadDll]` 并重启 MacType 后，客户端进程模块列表里已经没有 `MacType64.dll` /
`Easyhk64.dll`。`scripts/close-smoke.ps1` 连跑 4 次全过，另有一次在流式回复中途关窗口也干净退出；
事件日志里最后一条 gdi32full 崩溃是 00:40:46，在改配置之前。`ui-smoke.mjs` 同样通过。
