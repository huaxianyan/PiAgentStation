# 改名 Seven Station、桌面壳换 Tauri（2026-11-18 凌晨）

## 一句话

产品与仓库改名 Seven Station：中心变 `SevenStation.Core`（Host），桌面客户端从 WPF + WebView2 换成
Tauri 2（Rust + WebView2），页面上的自绘窗口按钮取消，窗口交给系统标题栏。Host 里加了 Agent 名片
与能力表，Pi 是第一个、现在也是唯一的一个实现。

## 做完的

**改名**

- 仓库 `huaxianyan/PiAgentStation` → `huaxianyan/SevenStation`（GitHub 保留旧地址重定向），
  remote 已改成新地址。
- `src/MAStation` → `src/SevenStation.Core`，命名空间、程序集、exe 名一起换。
- 数据目录从 `%LOCALAPPDATA%\MAStation` 换成 `%LOCALAPPDATA%\SevenStation`，按用户要求不迁移，
  旧目录留着不动即可。环境变量 `MASTATION_*` → `SEVENSTATION_*`。
- 页面 localStorage 键 `piagentstation.*` → `sevenstation.*`。
- 脚本、README、AGENTS.md、RELEASE.md、发布说明模板里的名字与路径都跟着换。

**桌面壳换 Tauri**

- `src/SevenStation.Desktop` 现在是 Cargo 项目（`cargo build` 出 `sevenstation-desktop.exe`），
  WPF 的 csproj 与 XAML 已删除。
- 壳负责：读 `center.json` + `token.txt` 拼带令牌的地址、加载中心页面、记忆窗口位置（`window.json`）、
  离线页（`dist/index.html`，连不上时显示）、日志（`logs/client.log`）、单实例、系统选目录。
- 壳的命令：`pick_folder`（系统文件夹对话框）、`center_local`（中心是否在本机）。
  中心页面是远端来源，要在 `capabilities/center.json` 里放开 `remote.urls`，
  自定义命令要在 `build.rs` 的 `AppManifest::commands` 里登记，否则报 not allowed。
- 页面里：窗口按钮、拖动区、`has-window-chrome` 样式全部删掉；选目录改成
  `window.__TAURI__.core.invoke('pick_folder')`，失败再退回页面里的目录树。

**Host 的 Agent 边界（第一步）**

- `Agents/AgentDescriptor.cs`：`AgentCapabilities`（工具、思考等级、模型、上下文用量、压缩、扩展、
  技能、命令、附件）+ `AgentDescriptor`（id、名称、版本、是否就绪、能力表、信息行）+ `AgentRegistry`。
- `Agents/PiAgent.cs`：Pi 的版本、程序目录、会话目录、能力声明都在这里，Pi 专属信息不再散在 Host 里。
- 协议 `hello` 里 `pi` 换成 `agent`（主 Agent id）与 `agents`（名片数组）；设置页的 Agent 卡片
  按名片的信息行渲染；思考等级与模型面板按能力表决定显不显示。

## 补：长对话改成按窗口加载（同日收尾后）

症状：点开一条 3.6 万条消息的对话要卡约 5 秒。原因是两端都没有窗口化：
中心 `SendState` 把 `_store.Messages(id)` 全量塞进一条 178 MB 的帧，前端 `renderThread()`
再为每条消息建 DOM（44.5 万个节点）。分环节实测：读库 1.3 s、逐条解析 0.7 s、重新序列化 1.2 s、
前端 `JSON.parse` 0.46 s、建 DOM 1.3 s。

改法：

- `ConversationStore.MessageWindow(id, limit, skipFromEnd)` 用 `ORDER BY seq LIMIT/OFFSET` 取一段并给出总数，
  替掉原来全量的 `Messages(id)`（只有 `SendState` 一个调用方）。
- `SendState` 只发最后 `MessagePageSize = 120` 条，附 `messageTotal` 与 `hasMore`。
- 新命令 `load_older { key, loaded }`：`loaded` 是界面已有条数，返回它前面那一段，回包是 `older_messages`。
- 前端 `session.raw` 存原始消息，是整个会话的唯一事实来源；`buildItems(raw)` 重建 items 与 toolIndex。
  实时消息在 `message_end` 时写回 raw，正在生成的那条（`session.liveId`）在重建时单独留住。
  换来的是往前翻页、流式输出、重连三条路径不会互相打架。
- 顶部出现「加载更早的消息」（`.older-row`），只在 `hasMore` 时给；翻页时 `renderThread(true)`
  按「离底部距离」保锚点，视线不跳。

实测（3.6 万条那条）：首开 110 ms、61 条、1670 个节点；每翻一页 45–56 ms、+63 条；
连翻三页后 ids 仍唯一、滚动锚点偏差 0 px。

还没做：翻到很后面时整段会重画（250 条时 6 千节点还行，几千条时需要虚拟滚动）；
页边界正好切开一次工具调用时，那个步骤会显示成未完成。

能做的事：

- 允许连接：改 `settings.json` 的 `Listen`；切局域网时用 `netsh advfirewall` 放行端口，需要时 UAC。
- 访问令牌：复制、重新生成（带二次确认；改完重启服务才生效）。
- 打开访问地址、数据目录、日志目录；最近 6 行日志只读不写。

两个坑记一下：

1. **WPF 工程的 `wwwroot` 不会自动进输出**，`<Content Update>` 匹配不到任何项，
   要写 `<Content Include="wwwroot\**\*" CopyToOutputDirectory="PreserveNewest" />`，
   否则窗口一片空白。
2. **桥接要发对象不要发 `JSON.stringify` 的字符串**。原生用 `PostWebMessageAsJson` 回包时，
   JS 侧 `event.data` 已经是对象，再 `JSON.parse` 会抛 `"[object Object]" is not valid JSON`。

**未完成：托盘。** WinForms `NotifyIcon` 与 `H.NotifyIcon.Wpf` 都试过，放在窗口可视树里、
放进应用资源里、给不给图标都试过，这台机器上都是启动约 2 秒后 `gdi32full.dll` fail-fast

### 补二：托盘崩溃的根因是 MacType

这台机器装着 MacType（`MacTray` 在跑），它把 DLL 注入进程后，
`gdi32full.dll` 里会 fail-fast（`0xc0000409`，WER 记 BEX64），
表现就是控制台启动约 2 秒后无声退出。把 `SevenStation.Control.exe` 加进
MacType 的排除名单后不再复现——换机器或重装系统时要记得这一步。

顺带三个坑：

- **托盘图标不能读 exe 里那张 `.ico`**：它是 PNG 压缩帧，转成 HICON 后是空白的，
  通知区域里只剩一个看不见的透明图标。现在改成用 WPF 直接画（32×32 深色圆角方块 + 白 π）。
- **WebView2 不认 `-webkit-app-region: drag`**，标题栏拖不动。改成标题栏 `mousedown`
  发消息给原生，原生 `ReleaseCapture()` + `SendMessage(WM_NCLBUTTONDOWN, HTCAPTION)`，
  贴边吸附和双击最大化一并交给系统。
- **`WindowStyle="None"` 没有窗口阴影**：即使把 `WS_CAPTION`/`WS_THICKFRAME` 加回去、
  调 `DwmSetWindowAttribute(DWMWA_NCRENDERING_POLICY)`，Win10 上仍然没有可见投影
  （实测窗口外像素与窗口内一致，无渐变）。现在靠页面里 `body::after` 画一圈
  1px `rgba(0,0,0,.14)` 描边把边界交代清楚。

### 补三：控制台推倒重做为 Tauri（WPF 那版已删除）

之前那版是 WPF + WebView2，跟客户端两套外壳，用户指出后重做。现在
`src/SevenStation.Control` 是标准 Tauri v2 工程，和 `src/SevenStation.Desktop` 同一套写法：

- `Cargo.toml`：`tauri = { features = ["tray-icon", "image-ico"] }`、`uuid`（令牌）、`time`（运行时长）
- `build.rs`：自定义命令写进 `AppManifest`，能力表里才允许页面调用
- `capabilities/control.json`：`core:default` + 八个 `allow-*`
- `dist/index.html`：就是原来那份页面，桥从 `postMessage` 换成 `invoke` / `listen`
- `src/core.rs`：服务与进程（`sc`、`tasklist`、`netsh`）、配置与令牌、日志与运行时长、提权
- `src/main.rs`：窗口、托盘、八个命令、3 秒轮询

几个决定：

- **提权不再猜自己是不是管理员**：直接做，`sc`/`netsh` 返回 5（拒绝访问）时再拉 UAC
  重跑一次，子进程走 `--do start|stop|autostart-on|firewall <端口>`，做完就退。
  少一次权限自检，流程也只有一个定义点。
- **拖动交给 `data-tauri-drag-region`**，不再自己发 `WM_NCLBUTTONDOWN`。
- **托盘图标用 `default_window_icon()`**（即 `icons/icon.ico`），Tauri 用 `image` crate 解 PNG 帧，
  WPF 那版读出来是空白的问题在 Tauri 这条路上不存在。
- **crate 名不许带点**，所以产物是 `sevenstation-control.exe`，打包时改名成
  `SevenStation.Control.exe`（和 `SevenStation.Core.exe` 对齐，MacType 排除名单也照这个名字写）。
- 发布脚本 `scripts/build-release.ps1` 多一个产物：`SevenStation-control-<版本>-win-x64.zip`。

`SevenStation.slnx` 里那行 WPF 项目已删掉（Tauri 不进解决方案）。

### 补四：拖动与托盘图标的两个具体决定

- **拖动不用 `data-tauri-drag-region`**：那条路要先有 `core:window:allow-start-dragging`
  这类窗口权限，属性加上了却没反应（双击最大化能work是因为那是我们自己发的命令）。
  现在标题栏 `mousedown` 发 `window_ctl { what: 'drag' }`，Rust 侧调 `window.start_dragging()`，
  和 Tauri 自己那份实现同一条路径，不依赖注入脚本。
- **托盘图标单独一张 `icons/tray.png`**：直接用客户端的 `icon.ico` 会和客户端托盘撞脸。
  现在这张是浅底深字（`#f7f7f9` 圆角块 + 深色 π 加细描边），客户端是深底，托盘里能分开。
  顺带避开了直接从 `.ico` 取图那条路。

### 补五：图标定为 Segoe UI Semibold 的 π，设置卡改 A′

- **图标不再手画路径**：用户说手画的像板凳。现在用 `design/make-icons.py` 把
  `C:\Windows\Fonts\segoeuib.ttf`（Segoe UI Semibold）的 π 按包围盒居中栅格化，
  一次生成三样东西：控制台 `icons/icon.ico`+`icons/tray.png`（浅底深 π）、
  客户端 `icons/icon.ico`（深底白 π），字形完全一致，只换配色。
  改留白或字体就重跑这个脚本，别手改 png/ico。
- **标题栏的小号 π 用同一个字体**（CSS `font-family: "Segoe UI Semibold"`），不再用默认字体渲染。
- **「允许连接」分段控件 → 「局域网连接」开关**（用户定的 A′）：行高 30 → 36px、
  键名列 76 → 80px；`.seg` 那套样式和 `scopeSeg` 的点击逻辑一起删掉，
  命令 `set_scope(scope: String)` 换成 `set_lan(on: bool)`，能力表跟着改名。
- **地址显示不再露 0.0.0.0**：局域网开着时用 `local_address()`
  （UDP 连 8.8.8.8 问路由表，不发包）拿本机内网 IP，页面把监听地址里的 0.0.0.0 替换掉再显示、再复制。

### 补六：标题栏那枚 π 要跟图标同色；底边那条线被裁掉

- 标题栏的 `.mark` 原来是深底白 π（照着客户端画的），和新的浅底图标不一致。
  现在改成浅底 + 深 π + `inset 0 0 0 1px` 描边，和 exe / 托盘同一套配色。
- **缺的那条边是底边，不是上边**：用户截图里 y=29 那行整行都是 212 灰，上边线在；
  而底边只有 2 个像素命中。原因是 125% 缩放下 WebView2 的视口是 627 CSS px
  而窗口只有 626，底部约 1.25px 被裁掉，`position: fixed; inset: 0` 的底边正好落在被裁的那几行。
  现在 `inset: 0 0 2px 0`，底边往上收 2px；收出来的那一条露出的是页面底色（同为 #f7f7f9），看不出来。
- 验证手法（都不用碰鼠标）：`PrintWindow(hwnd, hdc, PW_RENDERFULLCONTENT=2)` 能把被遮住的窗口也拍下来，
  四边像素分别在 y=0 / x=9 / x=908 / y=781 查到 212 灰，四边齐了。
- **踩过的坑**：`cp` 新 exe 到 `dist/` 时旧实例还锁着文件，`cp` 会失败但退出码看着像成功，
  结果启动的还是旧二进制（页面里还是旧 CSS）。改完 exe 要先 kill、等两秒、再 cp，然后用
  `document.styleSheets` 里那条规则确认新样式真的进去了。

### 补七：标题栏那枚 π 直接用图标文件；描边压深

- 上一版是用 CSS 画了个「浅底方块 + 字体 π + 描边」，比例和生成的图标对不上，
  用户一眼看出「你自己画的」。现在 `design/make-icons.py` 把托盘那张 64px
  同时写一份到 `dist/mark.png`，页面里就是 `<img src="mark.png">`，
  同一份像素，不存在两套画法。
- 上边缘那条线其实画出来了（`PrintWindow` 里 y=0 整行都是 212 灰），
  问题是 `rgba(0,0,0,.14)` 这圈线在浅色背景上和背景同亮度，看不出来。
  现在压深到 `.22`（193 灰），四边一致；换背景也分得清。

### 补八：窗口边框改用系统自带的（照客户端的做法）

前面几版都在无边框窗口里自己画 1px 描边，结果是 125% 缩放下渲染在两个物理像素上，
看着像重影，而上边那条又因为和浅色背景同亮度看不出来。用户提醒「看看客户端怎么做的」，
一看就明白：客户端 `WebviewWindowBuilder` **没关 decorations**，窗口边框、阴影、拖动、
贴边吸附全是系统画的，页面里根本没有标题栏。

于是控制台也改成一样：

- 删掉 `.decorations(false)`，用系统标题栏（图标、标题、最小化/最大化/关闭都是系统的）
- 页面里的 `.titlebar`、`.mark`、`.win-btn`、`body::after` 描边全部删除，
  连同 `window_ctl` 命令、`build.rs` 的命令清单、能力表里的 `allow-window-ctl`
- 系统 ✕ 通过 `CloseRequested` 拦下改成「收进托盘」，进程继续跑（验过：WM_CLOSE 后窗口隐藏、进程在）
- `design/make-icons.py` 不再往 `dist/` 写 `mark.png`（标题栏没了，那张图没用了）

教训：无边框自定义标题栏在 125% 缩放下要做到像素对齐很费劲，
而这个产品里客户端本来就是系统边框，控制台没有理由另搞一套。

### 补九：界面按方案 B 重排；`✕` 收托盘、退出只在托盘

- 上一轮删自绘标题栏时，连带把 `.body` 那条规则（`flex:1` / `gap` / `padding:16px`）也删了，
  于是卡片之间没有间距、14px 圆角贴在窗口边上，看着就是「莫名圆角」。补回来了，以后删 CSS 区间先查有没有夹带。
- 用户选了方案 B：页面 `#f7f7f9` + 白卡片 + 圆角 6px + 1px 细描边，卡片间距 10px，
  三张卡都带小号灰字块头（连接 / 启动与连接 / 最近日志），日志框圆角 5px 加细描边。
- 关窗行为维持：系统 ✕ → `CloseRequested` → 收进托盘，进程照跑；**退出只有托盘右键菜单那一条路**（用户明确要求）。
  页脚写明「关掉窗口不会停掉中心 · 右键托盘图标可退出」，解决发现性。

### 补十：点 ✕ 收托盘前先提示一句

- 用户反馈「点 ✕ 不会缩到托盘」。实测这条路是通的（`SC_CLOSE` 之后窗口 `IsWindowVisible` 变 False、进程还在），
  问题是**窗口一消失什么都没说**，看起来像没反应。
- 现在 `CloseRequested` 里先 `emit("toast", "已收进托盘，右键托盘图标可以退出。")`，
  1400ms 后再 `hide()`：用户看得见这句提示，再消失。实测 0.4s 时页面拿到这句文案，2s 后窗口不可见、进程还在。
- 注意：单实例插件会让「重复启动」转发给已隐藏的实例，测试时先全部 kill 再起，
  否则 `MainWindowHandle` 拿到的是隐藏窗口，`PrintWindow` 会拍出 0×0。

### 补十一：`✕` 改回即时隐藏，不加提示

用户不要延迟也不要提示，点了就收。`CloseRequested` 里只做 `prevent_close()` + `hide()`。

实测（用 `EnumWindows` 按类名找 `Tauri Window`，别用 `MainWindowHandle`）：

- 主窗口在收到 `SC_CLOSE` 后 **36ms** 变为不可见
- 进程数仍是 1，`ShowWindow(SW_SHOW)` 能把同一个窗口再显示出来（说明窗口没被销毁，托盘「打开控制台」能拉回来）
- **坑**：进程里还有两个窗口 —— `tray_icon_app`（隐藏）和 `moe.aruru.sevenstation.control-sic/-siw`（单实例插件那个，标记为可见但 0 尺寸）。
  `Process.MainWindowHandle` 会挑到单实例那个窗口，导致「窗口还在」的假象，量窗口是否真的收起来必须按类名找。
